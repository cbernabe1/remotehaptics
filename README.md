# Vibration Control

Vibration Control is a Flutter haptics laboratory for creating, testing, and saving vibration effects generated by the app itself.

It can also pair two phones over an encrypted WebSocket relay so one person can adjust the other phone's app-generated haptics after the host approves the session.

> **Scope:** This app does not change system-wide vibration intensity, call/SMS/alarm vibration, notification vibration, or other apps' haptics. It does not bypass Android or iOS safety limits.

## Goal

Make haptics easy to explore and control without unsafe system-level tricks:

- Let users feel strength and duration changes immediately.
- Keep the core experience usable offline.
- Support a deliberate, host-approved remote-control mode for two phones.
- Be honest about device, platform, and network limitations.

## Features

### Home

- Hold the graph to vibrate; vertical position controls strength.
- Duration is capped at 5 seconds per hold.
- Save presets and reuse the built-in preset library.
- Open a banner when a remote session is active.
- Works with the local Android haptics service or the Chrome preview service.

### Remote

- Host mode creates a six-digit room code.
- Controller mode joins with that code.
- The host must approve every controller before any haptic command is accepted.
- The controller can start, update, and stop playback on the host phone.
- The host reports playback status back to the controller.
- Either phone can end the session.
- Disconnects, app backgrounding, room expiry, and errors stop playback.
- Sessions are foreground-only and use an in-memory relay with no accounts or message history.

### Settings

- Toggle app-generated haptics.
- Inspect the Android capability report.
- Review platform limitations.
- Reset in-memory app data.
- Read privacy and scope information.

## How It Works

```text
Local mode
Flutter graph -> play request -> MethodChannel -> Android VibrationEffect

Remote mode
Controller graph -> WebSocket -> Relay room -> Host app -> Android VibrationEffect
                                      |
                                      +-> playback status back to controller
```

The remote relay enforces room roles, approval, rate limits, message-size limits, and expiry. It stores no accounts, names, messages, or room history.

- `web_socket_channel` for remote transport
- Native Android Kotlin bridge for vibration

## Requirements

- Flutter 3.47.9 or a compatible stable release
- Android SDK and a device/emulator running Android 8.0 (API 26) or newer for native haptics
- Node.js 20 or newer for the relay
- Chrome for the simulated web preview
- macOS and Xcode for iOS builds

On this Windows host, use `npm.cmd`; the PowerShell `npm.ps1` shim is blocked by execution policy.

## Run Locally

### Web preview

```powershell
flutter pub get
flutter run -d chrome
```

Chrome uses simulated capabilities and cannot validate real vibration strength.

### Android

```powershell
flutter pub get
flutter devices
flutter run -d <device-id>
```

The app expects a physical Android device for meaningful haptic validation.

### Remote mode with a local relay

Terminal 1:

```powershell
npm.cmd --prefix relay install
npm.cmd --prefix relay start
```

Terminal 2:

```powershell
flutter run -d chrome --dart-define=RELAY_URL=ws://localhost:8080/ws
```

For a physical phone on the same Wi-Fi:

```powershell
flutter run -d <device-id> --dart-define=RELAY_URL=ws://<computer-lan-ip>:8080/ws
```

The computer firewall must allow inbound traffic on port `8080`.

Android emulators default to `ws://10.0.2.2:8080/ws`. The relay URL can also be entered on the Remote screen.

## Deploy the Relay

The relay is a small Node.js service in `relay/`. It exposes:

- `GET /healthz`
- WebSocket endpoint at `/ws`

### Render free tier

Render deploys from GitHub or GitLab. Initialize and push this project first, then create a **New → Web Service** with:

| Setting | Value |
|---|---|
| Language | Node |
| Root Directory | `relay` |
| Build Command | `npm ci` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |
| Instance Type | Free |
| Environment variable | `TRUST_PROXY=1` |

Your public relay URL will look like:

```text
wss://<service-name>.onrender.com/ws
```

Use that URL in the app:

```powershell
flutter run -d chrome --dart-define=RELAY_URL=wss://<service-name>.onrender.com/ws
```

Free Render services sleep after 15 minutes without HTTP or WebSocket traffic. They are suitable for testing, not production. A restart clears all in-memory rooms.

### Docker

The included `relay/Dockerfile` also works with any container host:

```powershell
docker build -t vibration-relay relay
docker run --rm -p 8080:8080 vibration-relay
```

Put the container behind a TLS-terminating proxy before exposing it publicly.

## Known Limitations

- Only app-generated haptics are controllable.
- Playback is foreground-only.
- Remote mode needs a reachable relay and explicit host approval.
- Remote sessions end when either app goes to the background.
- Remote playback is capped at 5 seconds per hold and 30 minutes per session.
- Settings and presets are not persisted yet.
- iOS native haptics are not implemented.
- The package identifier `com.example.vibration_control` is still a placeholder.
- No public relay is deployed, and two-phone validation is still pending.
- Android output is limited by the device's public vibration API and hardware.
